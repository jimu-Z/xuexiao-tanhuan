# 学生谈心谈话系统 — 当前领域约束（v9）

> 部署状态说明：本文历史记录中的“未部署”表示本工作区未执行对应生产部署；用户可能自行部署，线上运行版本和行为未经本工作区独立核验。已交付的 2026-11-09 本地基版及其后源码修复区别见根目录 `HANDOFF.md`。

## 当前上线范围

核心业务仅包括：教师、学生信息（含 2026-10-28 起的学生照片）、谈话会话、学生谈话记录、附件、标签、模板。保留个别谈话和集体谈话，管理端以会话为列表根节点，在同一“谈话管理”页面查看参与学生记录。

统一查询和统计分析属于本期上线范围，所有统计与查询必须遵循全校/本学院数据边界。预约、预警、大屏、谈话跟进、学生反馈和“我的记录”仅保留代码与数据，菜单隐藏。`Student-UI` 源码保留，当前发布约定不部署学生端或监听 6090；实际远程 Nginx 监听状态需另行核验。

## 角色与数据范围

| 角色 | roleKey | 数据范围 | 关键约束 |
|---|---|---|---|
| 内置超级管理员 | `admin` | 全校 | 全部权限 |
| 校管理员 | `school_admin` | 全校 | 全校业务管理；不能修改、停用或删除内置 admin 账号；可管理其他校管理员。后端仍有 `admin` 专属操作，例如代码生成的建表接口，不能认定两者所有功能完全相同；当前源码的创建按钮按真实角色显示，尚未部署 |
| 院管理员 | `college_admin` | 本学院及下级 | 管理本学院全部业务、教师、年级和班级；可升降本学院院管理员，但不可降级自己或最后一名启用院管理员 |
| 老师 | `talk_teacher` | 本学院及下级 | 查看本学院全部业务数据；教师名单只读；学生可增改导入导出但不可删除 |

旧 `talk_secretary`、`talk_counselor` 统一迁移到 `talk_teacher` 并停用。岗位（书记、副书记、辅导员、班主任等）仅作为教师资料展示，绝不决定权限。

教师 Excel 导入的“角色”列只允许老师、院管理员、校管理员，分别对应 `talk_teacher`、`college_admin`、`school_admin`；更新模式按该列替换业务角色，保留无关角色。仅全局管理员可分配或修改校管理员；院管理员只能管理本学院，不能降级自己或最后一名启用院管理员。内置管理员账号禁止通过教师导入修改。

教师、登录账号和角色以每行独立事务提交，单行失败全部回滚并继续下一行。兼容没有“角色”列的旧模板：新账号默认老师，已有管理员角色保留。

角色改变时撤销已有登录会话。请求鉴权还必须从数据库刷新当前账号状态、角色、学院和菜单权限，不能将 Redis 旧角色缓存作为授权真相；这样并发登录或旧请求写回缓存也不能持续保留已撤销权限。此路径增加每次认证请求的用户和角色菜单查询。

当前工作区源码还排除了停用或逻辑删除角色对角色判断、菜单权限、菜单路由及前端角色键的影响；隔离回归及限制见根目录 `docs/系统核查进度清单.md`。这一修复尚未部署，生产运行版本未独立核验。

当前工作区的系统数据范围仅接受 `1` 全部、`2` 自定义、`3` 本部门、`4` 本部门及下级、`5` 仅本人；角色配置写入校验上述范围及 `0` 正常、`1` 停用状态。切面遇到无有效角色范围时拒绝查询，不能把未知值理解为全部数据；校管理员和内置超级管理员的既有全校特殊规则仍适用。部门列表没有用户别名，范围为“仅本人”时不返回部门数据。单角色五种范围及部分多角色权限组合已有隔离接口证据，详见根目录 `docs/系统核查进度清单.md`；本段新防护未部署。

2026-11-09 本地源码追加边界：院管理员或老师关联的学院已逻辑删除时，业务学院范围使用拒绝值；全局管理员仍按全局范围处理。该变更晚于已交付的 11 月 9 日本地基版，隔离回归见根目录进度清单，生产版本未独立核验；停用但未删除学院不在该变更范围内。

教师和院管理员的 `sys_user.dept_id` 必须直接指向 `dept_type=college` 的学院节点；缺失或指向其他层级时，业务查询使用 `collegeDeptId=-1` 失败关闭，不返回数据。

## 业务权限

| 资源 | 老师 | 院管理员 | admin / 校管理员 |
|---|---|---|---|
| 教师资料与账号 | 本学院只读 | 本学院增删改、导入、角色升降 | 全校全部操作 |
| 学生信息 | 本学院查看全部字段、筛选、新增、修改、导入、导出；不可删除 | 本学院全部操作 | 全校全部操作 |
| 年级/班级 | 只使用已有班级 | 本学院增删改 | 全校增删改 |
| 谈话会话/记录/附件 | 本学院全部可见、可导出；创建人或登记为参与人的教师可写/删除 | 本学院全部可写 | 全校全部可写 |
| 学院标签/模板 | 本学院共同维护 | 本学院共同维护 | 全校全部操作 |
| 系统内置标签/模板 | 全校可读可用，不可维护 | 全校可读可用，不可维护 | 可维护 |

学生手动新增仍只建立资料。学生 Excel 导入创建 `sys_user`：用户名为学号，初始密码 `123456` 使用 BCrypt 存储，分配 `talk_student` 角色；新账号保持停用，学生端、角色菜单及部署范围暂不开放。覆盖导入只同步已有学生账号的姓名和班级，不重置密码、不改变启停状态或角色。用户名被非本学生账号占用时整行拒绝，禁止接管教师或管理员账号。删除学生仍保留历史学生账号。

学生导入教师列仅检查同学院教师资料存在，不检查岗位、教师角色或启停状态；教师资料对应的管理员也可绑定。支持姓名或工号，同名需用工号，多人用顿号、逗号或分号分隔。按用户最新确认，管理关系通过 `talk_class_manager` 绑定班级与教师，学生通过所属班级获得管理教师；导入不再写入 `talk_student_manager`，旧表保留供审计，不自动删除历史数据。旧 `talk_teacher_class` 按名称关联仅在学院内该班级名称唯一时参与匹配；有歧义时须核对并建立明确的班级 ID 绑定。关联表示管理归属，不取代现有学院数据权限。隔离回归及其限制见 `docs/系统核查进度清单.md`，生产版本未核验。

2026-11-09 用户确认：校管理员管理全校学生；院管理员和老师可查看、维护本学院所有班级学生，负责班级只标识管理对象，不限制跨班谈话和协作。老师可修改同院其他班级学生资料，操作需要留痕。同学院老师可查看本学院谈话内容（包括心理健康、家庭困难等内容）；会话修改和删除由创建人或登记的系统老师负责，院管理员可管理本学院会话。隔离测试覆盖范围和日志限制见 `docs/系统核查进度清单.md`。

导入每行使用独立事务：组织、学生、账号、角色和关联全部成功才提交，任一步失败回滚当前行并继续下一行。预览不写数据库；重复学号跳过模式不补建账号/关联，要处理已有学生须选择覆盖模式。`talk_student_account` 保存明确账号归属，删除学生时保留归属并清空学生ID，允许同学院有权限账号安全重导；未知归属的遗留同名账号不能接管。手动编辑有明确归属的学生学号、姓名、班级会在事务内同步账号；密码、角色和启停不变。新增三张表通过 `sql/student_import_managers_v10.sql` 在部署新后端前创建，首次把旧教师班级关联按学院转换为班级ID关系，重跑不扩大已有精确关系；不直接重跑 v9 初始化迁移。

## 数据权限实现

- 业务读写统一通过 `TalkPermissionUtils` 判断精确角色与学院。
- 学生、会话、记录、附件、标签、模板和教师的列表查询在 Service 层注入参数化 `collegeDeptId`；禁止依赖前端菜单作为安全边界。
- 会话创建时从全部参与学生上溯学院，禁止空参与人或跨学院集体谈话，并把学院写入 `talk_session.college_dept_id` 作为历史快照。
- 老师调动学院不迁移历史谈话；其对原学院谈话立即失去访问权。
- 老师对会话、记录和附件的写操作同时校验学院及会话写权限：创建人或登记在 `talk_session_participant` 的系统教师可写；自定义谈话人不赋予账号权限。院管理员和全局管理员按各自范围管理。历史纯文本谈话人不会自动获得参与权限。
- Mapper 只使用 `#{}` 参数化条件。框架 `@DataScope` 仅用于系统部门树等通用模块，不替代谈话业务的显式范围校验。

## 标签、模板与历史

- `talk_tag.scope_type` 使用 `system` / `college`，学院定义通过 `college_dept_id` 归属。新增标签的内部标识由后端生成；修改名称不改变标识。
- 模板沿用 `template_type=system/personal`；`personal` 在 v9 中表示“学院模板”，并通过 `college_dept_id` 归属，不再表示个人私有。
- 现有标签和模板迁移为系统内置。
- `talk_session_tag.tag_value` 保存的是历史标签标识（兼容旧 JSON 格式），会话/记录正文保留历史内容；修改、停用或逻辑删除定义不会改写已存标识。名称不是随会话保存的快照：页面通过当前启用标签映射显示名称，改名可改变历史页面显示；停用或删除后映射可能缺失，历史名称展示策略仍待决定。
- 记录及创建反馈的新跟进状态只允许 `none`（无需跟进）、`pending`（待跟进）、`in_progress`（跟进中）、`completed`（已完成）。历史未知状态继续可读；更新未提交状态字段时不重写旧值，不启用隐藏的跟进菜单。

## 删除语义

删除谈话会话为物理级联删除：先尝试删除实际附件文件并记录失败日志，再在事务中删除 `talk_attachment`、`talk_student_record`、`talk_session_tag`、`talk_session_participant` 和 `talk_session`。标签和模板定义仍使用逻辑删除，以避免影响可追溯性。

## 组织结构

`sys_dept` 层级为学校 → 学院 → 年级 → 班级，学生挂在班级节点。老师可在本学院已有班级间移动学生；院管理员可维护本学院年级与班级，但不可修改学院节点或跨学院移动组织。

## 本地稳定性收尾（2026-10-21）

- 附件读取统一使用 `/ruoyi-system/talkattachment/download/{attachmentId}`，Service按会话学院校验；老师可读本院他人谈话附件。已登记附件的静态地址与通用下载地址禁止读取，含编码前缀和路径别名。头像等非谈话资源保留原用途；Nginx不得另设公开附件目录映射。
- 谈话修改合并原值后校验类型、日期、谈话人及参与学生。个别谈话必须一名学生，参与学生不能重复；逐条/批量删除学生记录必须保留至少一人，清空谈话应删除整个会话。旧的裸会话新增接口拒绝写入，统一从发起谈话创建会话与记录。
- 记录新增、删除及会话修改使用同一父会话事务锁和记录当前读，防止并发绕过人数限制。历史脏数据只报告，不批量修复。
- 统计分母仍为当前学院学生名单，不按在读状态额外过滤；学生转院不迁移历史会话学院快照。
- 本地候选包通过 `python scripts/create_candidate.py` 生成（仓库根目录运行）；测试/构建失败即停止，保留INCOMPLETE目录，不能用于部署。
