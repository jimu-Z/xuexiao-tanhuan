# 学生谈心谈话管理系统介绍

本系统面向高校学生工作部门、学院管理人员和参与学生谈话的教师。校级管理员维护组织和授权，学院按归属管理师生与谈话，教师在权限范围内登记谈话、补录历史和导出文书。

## 功能与使用场景

| 功能 | 可以完成的工作 |
| --- | --- |
| 工作台与统计 | 查看权限范围内的师生和谈话概况，进入常用业务页面 |
| 组织与师生管理 | 维护学院、年级和班级，管理教师账号、学生档案与班级负责人 |
| 师生资料导入 | 下载表格模板，按学院和班级导入资料。学生导入支持预览、逐行检查、重复学号处理和结果反馈 |
| 谈话登记 | 发起个别或集体谈话，记录时间、地点、教师参与人、学生、内容、标签和附件 |
| 历史补录与查询 | 上传历史谈话表格，筛查疑似重复项后选中导入。通过学生、时间和谈话条件查找历史记录 |
| 模板与标签 | 维护谈话模板和标签，发起谈话时套用模板正文并按实际情况编辑 |
| 台账与文书 | 导出学生台账和谈话数据。个别谈话可生成 Word 文书，集体和批量导出可按学生生成文书并打包附件 |
| 系统管理与审计 | 配置账号、角色、菜单和字典，查询操作日志和登录日志 |

## 角色与数据范围

| 角色 | 默认业务范围 | 典型操作 |
| --- | --- | --- |
| 系统管理员 `admin` | 全校 | 维护系统、组织、账号和授权 |
| 校管理员 `school_admin` | 全校 | 管理全校师生和谈话业务，维护校级模板与标签 |
| 院管理员 `college_admin` | 本学院 | 管理本学院师生、谈话、角色和学院业务配置 |
| 老师 `talk_teacher` | 本学院 | 查阅学院谈话，维护符合权限条件的学生和谈话记录 |

具体权限以启用的角色、账号学院归属和菜单授权为准。老师修改谈话时，还需符合创建人或登记参与教师等业务条件。辅导员、班主任等岗位用于描述人员职责，系统授权通过角色配置。学生调整学院后，历史谈话保留原会话的学院归属。

## 业务流程

### 从组织初始化到首场谈话

1. 管理员建立学院、年级和班级，配置教师账号、角色和班级负责人。
2. 教师或管理员下载系统生成的学生模板，按学号和组织归属填写。先提交少量数据，检查预览与导入结果，再导入完整台账。
3. 教师发起个别或集体谈话，选择学生和参与教师，填写谈话内容与标签，按需上传附件。
4. 保存后打开谈话详情，核对参与学生、教师和附件。归档时按需要导出 Word 文书或批量打包。

集体谈话的学生需来自同一学院。系统保存一场谈话的会话信息，并为关联学生保留对应记录。登记多个参与教师时，参与关系随会话保存。

### 批量补录历史谈话

1. 从历史谈话导入入口下载当前模板。填写学生和谈话信息，系统教师按工号匹配并校对姓名。
2. 上传后核对预览中的匹配结果与异常项。同一学生同日的疑似重复项默认跳过，可逐条复核。
3. 确认导入选中的记录，通过谈话查询抽样检查学生、学院和参与人。

## 技术组成与部署范围

管理端使用 Vue 2 和 Element UI。管理端请求通过 `/prod-api/` 转发到 Java 后端。后端基于 RuoYi-Vue、Spring Boot 和 MyBatis，MySQL 保存业务与权限数据，Redis 提供验证码等短期数据存储，上传文件保存在后端配置的持久化目录。

标准部署运行管理端和后端。`Student-UI/` 保留学生登录、预约和谈话反馈相关源码。学生端、预约与预警入口的实际开放范围以部署配置、菜单和账号授权为准。

使用真实学生资料时，按学校要求授权访问和导出。备份应同时覆盖 MySQL 数据库与附件目录。对外分享文书前检查身份信息、谈话内容和附件。
